Set it up

  1. Add AltWarden to your server. The invite asks only for the permissions its features use.
  2. In Server Settings, Roles, drag AltWarden's role above the role it will give out.
  3. Run /setup, or open the dashboard, and pick a verified role and a verification channel. Unless you're an Administrator, the role has to sit below your own highest role.
  4. Lock your channels so only the verified role can see them, and leave the verification channel visible.
  5. Open Health on the dashboard, or run /health, to catch anything missing.

Switching from another bot? Run /import-members with your existing verified role, and those members won't be asked to verify.

Lock down your server

Set the verification channel so new members can read it but can't chat in it.

Permission in the channel@everyoneAltWarden
View ChannelAllowAllow
Read Message HistoryAllowAllow
Send MessagesDenyAllow
Embed LinksAllow

Then choose one of two ways to keep new members out of everything else.

  • Unlock with the verified role. On each channel or category, deny View Channel for @everyone and allow it for the verified role. Keep the verification channel visible to @everyone.
  • Restrict with an unverified role. Turn on the unverified role in Rules. On each channel or category, deny View Channel for that role, and allow it in the verification channel. This keeps your current permissions, but members who joined earlier won't have the role.

Actions

ActionWhat happens
WatchThe match is recorded and the member gets in. Use this to learn what a rule would catch.
DenyThe member isn't verified and can try again.
KickThe member is told why, then kicked.
BanThe member is told why, then banned.

Every enabled check runs on every attempt, and the strongest action wins. A failure set to Deny can't hide a match set to Ban.

Presets

PresetMeant for
GentleLearning. Nothing blocks anyone, and everything is recorded.
StandardMost servers. Stops what's clearly hostile, and watches what could be innocent, such as VPNs, private windows and privacy extensions.
StrictServers under attack. Turns on Auto Kick. Expect some real members to need staff help.

A preset changes nothing until you save. It never touches roles, channels, messages, logs, alerts, country rules, the help desk, the honeypot, cooldown or the two-factor rule.

How alt matching works

Each kind of evidence carries a weight, and the total sets the confidence.

EvidenceWeight
Same browser cookie100
Same browser fingerprint45, or 10 on phones, tablets and Chromebooks, which look alike
Same connection35, or 10 on mobile, VPN and carrier-shared addresses
Same kind of device, across browsers20

A total of 100 is confirmed, 70 is likely, and 30 is possible. By default AltWarden acts on likely or stronger, so a shared home connection alone never stops a sibling, and neither do two phones of one model on the same Wi-Fi. Matches only ever compare accounts in your own server.

The account that verified first counts as the main one. If it verifies again later, it gets the action for the main account, not the action for an alt.

An alt of a banned account has its own action, so you can ban ban evaders and only deny everyone else. If two accounts are really two people, approve the appeal with "trust the link", or run /trust-accounts, and they won't match again.

Staff tools

Logs. Each rule has its own log module, and staff actions, verified members, Auto Kick, the help desk, the honeypot, raids, appeals and settings changes each have one too. Send each to its own channel, a whole category to one channel, or everything to one channel. Logs never show an IP address, email, cookie, fingerprint or country.

Alerts. Ping a role in a module's channel whenever that rule catches someone.

Bypass links. A link for one member that skips the checks you pick, for 1 to 168 hours. Every other check still runs, even on a server in Button mode. The link is shown to you once, and it's never posted in a log or a channel. If you choose to notify in a channel, the member is pinged in the verification channel, and presses Verify to get it.

Help desk. Adds a help button that opens a private thread with your support role. The first message is pinned and lists the member's failed attempts. Threads archive after a week of quiet, reopen when the member presses the button again, and close when the member leaves.

Honeypot. Anything posted in the trap channel is deleted, and the account is logged, timed out, kicked, softbanned or banned. Posts in threads under the channel are caught too. Roles you whitelist are ignored, and webhooks are only logged.

Appeals. Members who were stopped can explain themselves, and staff decide with buttons in Discord or on the dashboard. Approving an appeal from a banned account lifts the ban, so it takes Ban Members.

Raid mode. When joins spike, the rules tighten for a while and staff are alerted. A raid only ever makes a rule stricter. You can also start it with /raid.

Messages

The Messages page edits the verification message, the first message of each help thread, and the honeypot warning, with a live preview. The verification message is posted again when you change it, change the channel, or turn the help desk on or off. A changed message names the staff member who wrote it, with a link to report it.

The same page sets AltWarden's profile in your server: one of eight pictures, a name, a bio, and a name style with any of 12 fonts and 7 effects. Discord doesn't publish the name style fields in its reference, so a change on Discord's side could stop them working. If Discord refuses a style, the page says so and the rest still saves.

Who can do what

The Access page sets who can open each dashboard page and run each command, using Discord's own order. A member override decides first, then roles, then Everyone, then the required permissions. The server owner and Administrators always pass, so nobody gets locked out. Commands can also be limited to chosen channels.

The page also shows Discord's own command permissions, the same ones as Server Settings, Integrations. These decide who sees a command in Discord's list. Discord only takes changes to them from a person's account, so saving asks you to approve the change on Discord once. AltWarden makes the change and ends that approval straight away, and keeps no token.

Integrations

The Integrations page sends signed webhooks for member.verified, member.failed, appeal.opened, appeal.decided, raid.started and raid.ended. Check the signature by computing HMAC-SHA256 of t.body with your secret.

X-AltWarden-Signature: t=1793760000,v1=5f2b...

API keys answer one question, whether a member is verified:

GET /api/v1/guilds/{guild}/members/{user}
Authorization: Bearer aw_...

{"verified": true, "verified_at": 1793760000.0}

Common problems

What you seeWhat to do
Members don't get the roleIn Server Settings, Roles, drag AltWarden's role above the role it gives, and check it has Manage Roles. If you recreated the role, pick the new one on the Rules page.
A member says the link doesn't workLinks last an hour, or your Auto Kick time, and stop working once used or replaced. The member can press Verify in the channel for a new one.
Your server isn't on the dashboardYou need access to at least one page, which by default means Manage Server. Sign out and back in if your roles changed.
The verification message is goneRun /post-message, or press Post it again on the Messages page.
New members no longer see Discord's rules screenDiscord skips that screen for anyone given a role, so the Unverified role turns it off. Leave that role off if you rely on the screen.
A real member keeps failing one checkSend a bypass link that skips only that check, or verify them yourself with /verify-user.
A member wants their data deletedThey can do it themselves at My data, with no request to you or anyone else.

For anything else, run /health first, then open an issue on GitHub.
