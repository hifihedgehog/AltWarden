AltWarden

Security

AltWarden is built on one assumption: the database will leak someday. Everything below follows from planning for that.

What a stolen database gives an attacker

They would getThey would not get
Discord IDs, usernames and avatars of people who verifiedAny IP address, email address, cookie value or fingerprint
Attempt results and labelsAny Discord access or refresh token
Keyed hashes they can't read without the keyA way to connect one person across two servers

How it's built

  • Identifiers are hashed with HMAC-SHA256 under keys derived per server and per kind with HKDF from RFC 5869.
  • The master key lives in the process environment and never in the database or its backups.
  • Discord tokens are revoked under RFC 7009 right after one read, so none exist at rest. Staff who save Discord's command permissions approve one write, and that token is revoked the same way.
  • Verification links are stored as hashes, work for one member, and expire.
  • The sign-in state value is tied to the browser that started it.
  • Every page sends a strict Content Security Policy that allows scripts from this site only.
  • The page that receives Discord's code loads nothing and redirects at once, as RFC 9700 section 4.2.4 advises.
  • Browser libraries are copied into this site at fixed versions, so a compromised CDN can't reach members.
  • No admin tools listen on public addresses. The application binds to the local machine behind a proxy.
  • Request logs are off in the application, and the site's access log records no client addresses or page paths.
  • The bot asks only for the permissions its features use. It doesn't need Administrator.

Known limits

  • Browser checks can be forged. They run in the member's browser, so a custom client can report anything. They stop ordinary tools and raise the cost. Network, account and cookie-signature checks don't depend on that report.
  • A full takeover of the server defeats the hashing. Someone with both the database and the master key can test guesses against a hash. IPv4 has few enough addresses for that to work. Keeping the key separate protects against a stolen database or backup, which is how most leaks happen.
  • A running process sees real addresses for a moment. They exist in memory during a request.
  • Lists go stale. VPN and country data is refreshed weekly, and new VPN servers can slip through until then.
  • Root can't be read from a web page. No browser API reports it, and the services that do report it read it from a native app. The Modified phone check catches what rooting lets a phone do: pose as another model, or run firmware newer than the phone ever got. A rooted phone that changes neither passes, and so does a jailbroken iPhone.

Reporting a message

Server staff can rewrite the messages AltWarden posts, so each rewritten message names the person who wrote it. If one is a scam or harassment, tell that server's owner, report the message to Discord, and open an issue on GitHub with the server's name.

Reporting a problem

Report security problems privately through GitHub, not in a public issue.
